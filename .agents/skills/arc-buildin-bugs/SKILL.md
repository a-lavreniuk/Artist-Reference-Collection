# ARC — доска Таски / баги (Buildin)

Доска **Таски**. Баги — карточки с **Тип задачи = Баг**.  
Два режима: **триаж** (форма → карточки) и **работа** (колонка «В работе» → код).

Паттерн как у [arc-buildin-tasks](../arc-buildin-tasks/SKILL.md); отличие — фильтр Баг, поля формы, шаги воспроизведения.

Конфиг: [buildin-config.md](../arc-buildin-shared/references/buildin-config.md).  
Формат тела: [task-card-format.md](../arc-buildin-shared/references/task-card-format.md).  
Закрытие: [buildin-task-finish](../buildin-task-finish/SKILL.md).

## Режим A — триаж выгрузки формы

Триггер: пользователь прислал CSV/JSON из «Сообщить о проблеме в ARC бета» или путь к файлу.

```
- [ ] 1. Прочитать все строки (CSV и JSON эквивалентны)
- [ ] 2. Пропустить или пометить [Тест]: пустое/«Тест» в заголовке и описании
- [ ] 3. Объединить дубликаты (одинаковый раздел + суть)
- [ ] 4. Для каждого уникального отчёта — page create в Таски:
        Тип задачи → Баг, Статус, Source (url формы)
        children: heading_1 «Описание» + divider + текст триажа (H3 по полям ниже)
        секцию «Что сделано» при триаже не создавать
- [ ] 5. Статус при создании:
        реальный баг / серьёзно → «Бэклог» или «Готово к работе»
        идея / пожелание → «Бэклог» (в теле пометить как идея)
- [ ] 6. Таблица: ID формы → карточка → статус → объединения
```

### Содержимое под «Описание» (триаж)

Логические куски — `heading_3` + `paragraph` (не markdown `---`):

- Источник — ID формы, дата, тип обращения, критичность  
- Где — разделы ARC  
- Описание — кратко / подробно  
- Шаги воспроизведения  
- Вложения  
- Триаж — вывод агента  

`Source` → URL формы (`https://forms.yandex.ru/u/6a382e851f1eb55aed4c9c42`).

## Режим B — подхват «В работе»

Триггер: «возьми баг», «баги в работе», «продолжим баг».

```
- [ ] 1. database query: Статус=В работе AND Тип задачи=Баг
- [ ] 2. Если 0 — сообщить и остановиться
- [ ] 3. Если >1 — приоритет ниже; остальные списком
- [ ] 4. page get + block children → шаги воспроизведения, обход
- [ ] 5. Реализовать в ARC (или buildin-task-take по Codex)
- [ ] 6. После «ок» — buildin-task-finish (только «Что сделано» + Готово)
```

Дополнительно:

1. Сверять раздел ARC (Галерея, Метки, …) с `renderer/src/pages/`.
2. **Агент не переводит** карточку в «В работе» — только пользователь.

## Приоритет при нескольких «В работе» (баги)

1. Производительность / блокирует работу  
2. Серьёзный баг (не идея)  
3. Старше по дате отчёта в теле  

Остальные — списком, без автоматического старта.

## Связь с продуктом

- Виджет и форма: `docs/bug-report-widget.md`
- UI: `arc-ui-dev`
- Старт с Codex: [buildin-task-take](../buildin-task-take/SKILL.md)
- Тестовые `[Тест]` — не брать в работу; предложить архивировать / оставить в бэклоге

## Триггеры

| Фраза | Режим |
|-------|--------|
| «Выгрузил форму» / путь к CSV | A |
| «Разбери репорты» | A |
| «Возьми баг» / «баги в работе» | B |

## Формат отчёта

1. Режим A или B.  
2. Созданные/взятые карточки (имя + id/url), Тип задачи = Баг.  
3. Изменения в ARC.  
4. Статусы Buildin / «Что сделано».  
5. Что проверить вручную.
