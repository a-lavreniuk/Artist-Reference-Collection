# Взять задачу / баг из Buildin

Полуавтоматический старт: пользователь переносит карточку в **«В работе»** на доске **Таски** и говорит «возьми задачу» или «возьми баг». Агент читает карточку и действует по режимам поля **Codex**.

CLI: `buildin`. Конфиг: [buildin-config.md](../arc-buildin-shared/references/buildin-config.md).  
Формат тела: [task-card-format.md](../arc-buildin-shared/references/task-card-format.md).  
Skill CLI: [buildin-cli](../../../.agents/skills/buildin-cli/SKILL.md).

## 0. Preflight

```bash
buildin --json doctor
buildin --json whoami
```

При ошибке auth — не логиниться самим; предложить `buildin login --browser` или `BUILDIN_TOKEN` и ждать выбора пользователя.

## 1. Прочитать карточку

1. Собрать `query.json` (см. конфиг): `Статус` = `В работе` + `Тип задачи` по фразе:

| Фраза пользователя | Фильтр `Тип задачи` |
|--------------------|---------------------|
| «возьми задачу» / «задачу из В работе» | **Задача** |
| «возьми баг» / «баг из В работе» | **Баг** |
| «возьми» без уточнения | две query (Задача и Баг); если несколько — спросить |

2. `buildin --json database query <database_id> --body query.json`
3. **Одна** подходящая → брать. **Несколько** → спросить. **Ноль** → сообщить и остановиться.
4. `buildin --json page get <page_id>` + `buildin --json block children <page_id>` (и при необходимости `markdown get` для legacy-текста) → название, тело, свойства.
5. В теле ориентироваться на секции **«Описание»** / **«Что сделано»** (см. task-card-format); для работы нужен смысл из **Описание**.
6. Поле **Codex** (`multi_select`): `Нужна ветка`, `Нужен план`, `Хотфикс`.
7. **Codex пустой** → спросить режим, **не начинать** без ответа.

**Запомнить на всю сессию** (для **buildin-task-finish**):

- `buildin_page_id` — id страницы-карточки;
- `buildin_tip_zadachi` — `Задача` или `Баг`;
- `buildin_page_name` — название;
- `buildin_page_url` — `https://buildin.ai/<page_id>`.

Кратко пересказать: название, Тип задачи, статус, Codex, суть **Описание** (если «Что сделано» уже есть — упомянуть).

## 2. Приоритеты режимов

| Правило | Действие |
|---------|----------|
| **«Нужна ветка»** | Высший приоритет. **Никогда не писать код в `main`**, если этот тег есть |
| **«Нужна ветка» + «Нужен план»** | Сначала ветка, потом Plan mode |
| **Только «Нужен план»** | `main` без новой ветки → Plan mode |
| **«Хотфикс»** (без «Нужна ветка») | Agent mode, сразу к реализации |

Если есть и «Нужна ветка», и «Хотфикс» — **ветка побеждает**.

## 3. Режим «Нужна ветка»

```bash
git checkout main
git pull origin main
git checkout -b <branch-name>
```

**Имя ветки:** название на английский, kebab-case, **без** префикса `feature/`.

После создания ветки — `SetActiveBranch`.

Если **нет** «Нужен план» → **остановиться**, ждать «делай» / «реализуй».

## 4. Режим «Нужен план»

1. Если нужна ветка — сначала п.3.
2. `SwitchMode` → **plan**.
3. Анализ + вопросы до ясности.
4. **Не писать код** до «делай» / «реализуй» / одобрения плана.

## 5. Режим «Хотфикс»

Только без «Нужна ветка»: Agent mode, сразу к реализации.

## 6. После «делай» / «реализуй»

- `SwitchMode` → **agent** (если был Plan).
- Реализация; UI — **arc-ui-dev**.
- Для багов дополнительно: шаги воспроизведения, обход (см. **arc-buildin-bugs**).
- Закрытие: **git-task-finish** → **buildin-task-finish**.

## 7. Ограничения

- Не коммитить/пушить без просьбы.
- **Не менять статус** при старте — «В работе» ставит пользователь.
- Не создавать ветку, если задачу назвали в чате без «возьми задачу» / «возьми баг» — уточнить.

## Примеры

**Задача:** «Возьми задачу» → Тип задачи Задача + «В работе» → Codex → ветка/план/код.

**Баг:** «Возьми баг» → Тип задачи Баг + «В работе» → тот же Codex-workflow.

**Несколько в работе:** спросить, какую карточку брать.
