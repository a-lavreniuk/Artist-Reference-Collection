# Формат карточки Таски (Buildin)

Канон тела страницы на доске **Таски**. Свойства database — в [buildin-config.md](./buildin-config.md).

## Название

Свойство **Название**: суть правки в **3–4 слова** (не предложение).

## Структура тела (блоки редактора)

Порядок блоков:

1. `heading_1` — текст **«Описание»**
2. `divider` — сепаратор редактора Buildin (`"divider": {}`)
3. Свободный текст: `paragraph` и при необходимости `heading_3` для логических абзацев
4. `heading_1` — текст **«Что сделано»**
5. `divider`
6. Свободный текст: `paragraph` / `heading_3`

### Когда что писать

| Откуда работа | Что писать в тело |
|---------------|-------------------|
| Готовая карточка из Buildin (пользователь уже написал Описание) | Только секция **«Что сделано»** (H1 + divider + текст). Описание **не трогать**. |
| Работа сразу в чате, карточки не было | После триггера завершения — **полная** карточка: Описание + Что сделано |

Текст секций — свободная форма. Ссылку на PR / merge-коммит можно дать первой строкой в «Что сделано».

## JSON-хелперы

Rich text fragment:

```json
{ "type": "text", "text": { "content": "…" } }
```

Секция «Что сделано» (для `block append` к `page_id`):

```json
{
  "children": [
    {
      "type": "heading_1",
      "heading_1": {
        "rich_text": [{ "type": "text", "text": { "content": "Что сделано" } }]
      }
    },
    { "type": "divider", "divider": {} },
    {
      "type": "paragraph",
      "paragraph": {
        "rich_text": [{ "type": "text", "text": { "content": "…" } }]
      }
    }
  ]
}
```

Полный шаблон в `page create` — те же блоки, плюс перед ними «Описание» + `divider` + текст описания; затем «Что сделано» + `divider` + текст.

Команды:

```bash
buildin --json block children <page_id>
buildin --json block append <page_id> --body append.json
buildin --json page create --body page.json
```

Parent для append — **page_id** карточки (дети страницы).

## Антипаттерны

- Текстовый `---` / ` --- ` вместо блока `divider` — **запрещено** (не сепаратор редактора; `markdown put` так и портит карточки).
- Собирать структуру секций через `markdown put` — **запрещено**.
- Заголовки секций строкой `# Описание` внутри `paragraph` — использовать блок `heading_1`.
- Секция **«Результат»** / `## Результат` — устарело; канон — **«Что сделано»**.
- Затирать пользовательское Описание при закрытии готовой задачи.
- Менять Cursor / Тип задачи / Source при закрытии без запроса.

## Legacy

Старые карточки могут содержать один `paragraph` с текстом `## Описание` / ` --- ` / `## Результат`. При закрытии:

- пользовательское Описание не переписывать;
- append каноническую секцию `heading_1` «Что сделано» + `divider` + новый текст;
- если структура неоднозначна (уже есть «Что сделано») — спросить, не дублировать молча.
