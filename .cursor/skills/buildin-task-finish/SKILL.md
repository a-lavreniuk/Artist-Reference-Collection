# Закрыть задачу / баг в Buildin

Финальный шаг после **git-task-finish** (или вместо него, если git не нужен): обновить или создать карточку на доске **Таски** в Buildin.

MCP: `user-buildin`. Константы — [buildin-ids.md](references/buildin-ids.md).

## Когда выполнять

| Ситуация | Действие |
|----------|----------|
| Git-финал прошёл успешно | Обновить карточку Buildin |
| Git не требовался (только skills/docs/анализ) | Создать или обновить карточку Buildin |
| Git остановлен (тесты, конфликт, critical review) | Buildin **не трогать**, сообщить |
| Пользователь настаивает закрыть при незавершённой работе | «Готово» + в «Результат» указать, что не доделано |

## 1. Определить карточку

**Приоритет:**

1. **`buildin_page_id` из сессии** — запомнен при **buildin-task-take**.
2. **Нет `buildin_page_id`** — работа из чата → **создать** карточку (п. 4).
3. **`buildin_page_id` потерян**, но карточка из Buildin → спросить. **Не угадывать**.

Совместимость: если в сессии остался только старый `anytype_object_id` / `object_id` — сообщить, что доска в Buildin, и попросить выбрать карточку или `page_id`.

## 2. Сформировать секцию «Результат»

Текст секции:

```markdown
## Результат

[Ссылка на PR, если есть — первая строка]

5–10 предложений: что изменилось для пользователя, ключевые файлы, как проверить. Если неполно — отдельный абзац «что осталось».
```

- Заголовок ровно **`## Результат`** / блок `heading_2` с текстом «Результат».
- PR / merge-коммит / «PR не создавался».

## 3. Обновить существующую карточку

1. `API-getMarkdown` — прочитать тело.
2. Добавить «Результат»:
   - если секции ещё нет → `API-appendBlockChildren` с `block_id` = `page_id`, children: `heading_2` «Результат» + один или несколько `paragraph`;
   - если секция уже есть → дописать/заменить содержимое под заголовком (`API-updateBlock` для абзацев или, при установленном CLI и явном согласии, `buildin markdown put` после merge текста).
3. `API-updatePage`:
   - `properties` — **только** статус:

```json
{
  "Статус": {
    "type": "select",
    "select": { "name": "Готово" }
  }
}
```

**Не менять:** Cursor, Source, Тип задачи, Название и прочие свойства.

## 4. Создать карточку (работа из чата)

1. **Спросить Тип задачи:** «Задача» или «Баг».
2. **Название** — 2–3 слова по сути.
3. **Тело** (children при create или append после):
   - **Задача:** запрос из чата + «Результат».
   - **Баг:**

```markdown
## Описание
 ---
<описание проблемы из чата>

## Результат

<ссылка на PR + 5–10 предложений>
```

4. `API-createPage`:
   - `parent`: `{ "database_id": "<id из buildin-ids>" }`;
   - `properties`:
     - `Название` — title;
     - `Тип задачи` — select `Задача` или `Баг`;
     - `Статус` — select `Готово`;
     - `Source` — url, если была ссылка в чате;
   - **Cursor не заполнять**;
   - `children` — тело (heading/paragraph blocks).

## 5. Отчёт пользователю

- название;
- Тип задачи (Задача / Баг);
- статус «Готово»;
- url карточки;
- кратко — что в «Результат».

## 6. Связка

- Старт — **buildin-task-take**.
- Git — **git-task-finish** до этого skill.
- Порядок «закрой задачу»: git-task-finish → buildin-task-finish.

## Примеры

**Из доски:** «возьми задачу» / «возьми баг» → работа → «закрой задачу» → update по `buildin_page_id`, Готово + «Результат».

**Из чата:** спросить Задача/Баг → create в database Таски сразу в Готово.
