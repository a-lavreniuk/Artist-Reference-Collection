# Взять задачу / баг из Buildin

Полуавтоматический старт: пользователь переносит карточку в **«В работе»** на доске **Таски** (Buildin) и говорит «возьми задачу» или «возьми баг». Агент читает карточку и действует по режимам поля **Cursor**.

MCP: `user-buildin` (должен быть авторизован). Константы — [buildin-ids.md](../buildin-task-finish/references/buildin-ids.md). Для сырых API-вызовов через CLI — skill **buildin-cli**.

## 1. Прочитать карточку

1. Убедиться, что MCP `user-buildin` доступен (`API-getMe` или любой лёгкий запрос). При 401 — напомнить про Connect / OAuth в Cursor Settings → Tools & MCP.
2. `API-queryDatabase` с `database_id` из buildin-ids и фильтром:

```json
{
  "filter": {
    "and": [
      { "property": "Статус", "select": { "equals": "В работе" } }
    ]
  },
  "page_size": 50
}
```

3. Дополнительно по фразе пользователя и **Тип задачи**:

| Фраза пользователя | Фильтр `Тип задачи` |
|--------------------|---------------------|
| «возьми задачу» / «задачу из В работе» | **Задача** |
| «возьми баг» / «баг из В работе» | **Баг** |
| «возьми» без уточнения | обе; если несколько — спросить |

Для Задача/Баг добавить во `and`:

```json
{ "property": "Тип задачи", "select": { "equals": "Задача" } }
```

(или `"Баг"`).

4. **Одна** подходящая → брать её. **Несколько** → спросить. **Ноль** → сообщить и остановиться.
5. `API-getPage` + `API-getMarkdown` → название, свойства, тело.
6. Поле **Cursor** (`multi_select`) — теги: `Нужна ветка`, `Нужен план`, `Хотфикс`.
7. **Cursor пустой** → спросить режим, **не начинать** без ответа.

**Запомнить на всю сессию** (для **buildin-task-finish**):

- `buildin_page_id` — id страницы-карточки;
- `buildin_tip_zadachi` — `Задача` или `Баг`;
- `buildin_page_name` — название;
- `buildin_page_url` — url карточки (если есть).

Кратко пересказать: название, Тип задачи (Задача / Баг), статус, Cursor, суть описания.

## 2. Приоритеты режимов

| Правило | Действие |
|---------|----------|
| **«Нужна ветка»** | Высший приоритет. **Никогда не писать код в `main`**, если этот тег есть |
| **«Нужна ветка» + «Нужен план»** | Сначала ветка, потом Plan mode |
| **Только «Нужен план»** | `main` без новой ветки → Plan mode |
| **«Хотфикс»** (без «Нужна ветка») | Agent mode, сразу к реализации |

Если есть и «Нужна ветка», и «Хотфикс» — **ветка побеждает**.

## 3. Режим «Нужна ветка»

```bash
git checkout main
git pull origin main
git checkout -b <branch-name>
```

**Имя ветки:** название на английский, kebab-case, **без** префикса `feature/`.

После создания ветки — `SetActiveBranch`.

Если **нет** «Нужен план» → **остановиться**, ждать «делай» / «реализуй».

## 4. Режим «Нужен план»

1. Если нужна ветка — сначала п.3.
2. `SwitchMode` → **plan**.
3. Анализ + вопросы до ясности.
4. **Не писать код** до «делай» / «реализуй» / одобрения плана.

## 5. Режим «Хотфикс»

Только без «Нужна ветка»: Agent mode, сразу к реализации.

## 6. После «делай» / «реализуй»

- `SwitchMode` → **agent** (если был Plan).
- Реализация; UI — **arc-ui-dev**.
- Для багов дополнительно: шаги воспроизведения, обход (см. **arc-anytype-bugs**).
- Закрытие: **git-task-finish** → **buildin-task-finish**.

## 7. Ограничения

- Не коммитить/пушить без просьбы.
- **Не менять статус** при старте — «В работе» ставит пользователь.
- Не создавать ветку, если задачу назвали в чате без «возьми задачу» / «возьми баг» — уточнить.
- Не читать карточки из AnyType для этого workflow.

## Примеры

**Задача:** «Возьми задачу» → Тип задачи Задача + «В работе» → Cursor → ветка/план/код.

**Баг:** «Возьми баг» → Тип задачи Баг + «В работе» → тот же Cursor-workflow.

**Несколько в работе:** спросить, какую карточку брать.
