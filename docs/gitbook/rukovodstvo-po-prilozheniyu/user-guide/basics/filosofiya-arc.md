# Философия ARC

ARC построен вокруг простой идеи: референс должен быть легко сохранить, легко описать и легко найти спустя время. Библиотека не должна требовать от пользователя заранее разработанной сложной системы каталогизации. Организация может формироваться постепенно, по мере накопления материалов.

## Сначала материал, потом структура

Необязательно продумывать всю систему коллекций и меток до первого импорта. Можно сохранить файл, а затем решить, к какой коллекции он относится, какие характеристики для него важны и какие данные стоит вынести в пользовательские поля.

Такой подход особенно полезен для большой библиотеки. В начале работы пользователь может быстро собирать материалы, а когда определённый тип референсов начинает повторяться, создать для него устойчивую структуру.

## Файл и карточка — разные уровни

ARC разделяет физический материал и его каталогизацию. Файл существует на диске и нужен для использования в других приложениях. Карточка представляет этот файл в ARC и связывает его с коллекциями, метками и метаданными.

Это позволяет менять организацию библиотеки без необходимости изменять сам файл. Например, одну карточку можно связать с несколькими коллекциями или добавить ей новую метку, не создавая новую копию изображения.

## Организация должна помогать поиску

Коллекции, метки и пользовательские поля имеют смысл не сами по себе, а как способы быстрее находить материалы. Хорошая структура отвечает на практический вопрос: «Как я буду искать это через месяц?».

Коллекции подходят для группировки по проекту, задаче или любому другому устойчивому критерию. Метки удобны для характеристик, которые могут пересекаться у разных групп материалов. Пользовательские поля позволяют хранить собственные типы данных, когда стандартных метаданных недостаточно.

## Поиск должен масштабироваться вместе с библиотекой

Небольшую библиотеку можно просматривать вручную. По мере роста становится важнее поиск по текстовым данным, фильтры и AI-поиск.

Обычный поиск использует сохранённые в каталоге сведения. AI Семантика позволяет сформулировать визуальный запрос обычным языком, а «Похожие изображения» использует изображение как поисковый образец. Эти режимы решают разные задачи и могут использоваться независимо.

## Локальность — часть модели работы

ARC работает с библиотекой на устройстве пользователя. AI-модели также выполняются локально. Это означает, что производительность AI-поиска зависит от выбранной модели и аппаратного режима, а размер библиотеки и количество материалов влияют на время индексации.

При использовании облачной папки ARC не становится облачным сервисом: облачное копирование выполняет выбранный пользователем провайдер.

## Не нужно выбирать одну идеальную систему

В ARC можно одновременно использовать несколько способов организации. Один материал может находиться в коллекции проекта, иметь несколько меток и содержать значения пользовательских полей. Поиск затем может сочетать эти сведения с фильтрами или AI-запросом.

Поэтому структура библиотеки может эволюционировать вместе с рабочим процессом, а не требовать полной перестройки после каждого изменения требований.
