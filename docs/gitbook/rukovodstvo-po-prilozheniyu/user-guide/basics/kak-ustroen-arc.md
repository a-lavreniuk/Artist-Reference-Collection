# Как устроен ARC

Работу ARC удобно понимать как несколько связанных уровней: библиотека, файл, карточка и средства организации и поиска.

## Библиотека

Библиотека — рабочее пространство ARC, связанное с определённой папкой на диске. В ней находятся импортированные материалы и данные, необходимые приложению для их отображения и обработки.

В настройках можно посмотреть расположение текущей библиотеки и открыть её папку в проводнике. Если библиотека перемещается, путь к ней должен оставаться доступным ARC.

## Файл

Файл — физический объект на диске: изображение, видео или другой поддерживаемый материал. Именно файл открывается вне ARC и используется в других программах.

Во время импорта ARC копирует материал в рабочую папку библиотеки. Поведение исходного файла после копирования выбирается пользователем.

## Карточка

Карточка — объект каталога ARC, связанный с файлом. Она содержит представление материала в библиотеке и его организационные данные.

Карточка может быть помещена в коллекции, ей можно назначить метки и заполнить пользовательские поля. При просмотре карточки доступны действия с исходным файлом.

## Коллекции

Коллекция — логическая группа карточек. Она не является отдельной физической папкой и не требует копирования файлов. Коллекции позволяют собрать материалы по выбранному пользователем признаку.

Один и тот же материал может использоваться в нескольких логических группах, поэтому коллекции не ограничивают физическую структуру файлов на диске.

## Метки

Метка — характеристика, которую можно назначить карточке. Метки можно объединять в категории, чтобы поддерживать понятную систему классификации.

В отличие от коллекции, метка описывает свойство материала. Например, коллекция может отвечать на вопрос «для какого проекта нужен материал», а метка — «какая визуальная характеристика у него есть».

## Пользовательские поля

Пользовательские поля нужны для данных, которые не покрываются стандартными свойствами карточки. Их набор определяется пользователем и может быть адаптирован под конкретную систему каталогизации.

## Поиск

Поиск работает поверх данных библиотеки. В зависимости от режима можно использовать текстовый поиск, фильтры, AI Семантику или «Похожие изображения».

Для AI-поиска требуется отдельная подготовка: включить AI в настройках, установить модель и проиндексировать библиотеку. Без индекса AI-поиск не может сопоставлять запрос с материалами библиотеки.

## Связь между уровнями

В упрощённом виде схема выглядит так:

**Библиотека → файл → карточка → организация → поиск.**

Библиотека определяет рабочее пространство и расположение данных. Файл содержит сам материал. Карточка представляет его в ARC. Коллекции, метки и поля описывают карточку. Поиск и фильтры используют эти сведения, а AI-поиск дополнительно работает с визуальными признаками материалов.

Эта модель помогает понимать последствия действий. Удаление карточки и работа с исходным файлом — связанные, но не одинаковые операции; коллекция меняет логическую группировку, а не обязательно физическое расположение файла.
